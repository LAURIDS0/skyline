# SKYLINE TYCOON
### Build an airline. Shape the world. Dominate the skies.

**Skyline Tycoon** is an ambitious multiplayer airline and airport management simulation built around real-world aviation, real airports, real aircraft and a persistent global economy.

Start with a small airline and a limited budget. Acquire airports, construct terminals, purchase aircraft, establish international routes, hire employees and compete against other airline operators.

Build a regional airline into a global aviation empire.

Every airport has its own infrastructure. Every aircraft has operational requirements. Every route has an economy. Every decision has consequences.

This is more than an airline tycoon. It is an interconnected aviation world where players create, manage and compete in a living global market.

# GAME VISION

Skyline Tycoon aims to deliver a deep, realistic and highly detailed airline management experience directly in the browser.

The game combines several genres:

- Airline management simulation.
- Airport construction and infrastructure management.
- Economic and business simulation.
- Multiplayer strategy.
- Logistics and transportation management.
- Real-world geographical simulation.

The goal is to create a persistent world in which thousands of airports, aircraft, routes and companies can coexist.

## Design Philosophy

The game follows five fundamental principles.

**1. Every decision matters**

Aircraft purchases, ticket prices, airport investments, staffing and route planning should have meaningful financial and operational consequences.

**2. Everything is connected**

An airport cannot operate independently of its infrastructure. Aircraft require suitable runways and facilities. Routes depend on passenger demand, competition and airport capacity.

**3. Realism without unnecessary complexity**

The simulation should be detailed enough to reward strategic thinking while remaining accessible through a well-designed interface.

**4. A persistent multiplayer world**

Players should influence the same economy, compete for passengers, negotiate commercial agreements and build relationships.

**5. Continuous development**

New aircraft, airports, infrastructure, mechanics and gameplay systems should be possible without redesigning the entire architecture.

# AIRPORT CONSTRUCTION SYSTEM

The airport editor is one of the game's central features.

Players should be able to design and expand airports using a detailed 3D construction environment.

### Construction grid

- One grid field represents 10 meters.
- Real runway dimensions are used where available.
- Runways have fixed operational positions.
- Taxiways connect aircraft facilities.
- Buildings must have valid access.
- Infrastructure must satisfy operational requirements.

### Building categories

**Passenger infrastructure**

- Passenger terminals.
- Check-in counters.
- Security checkpoints.
- Passport control.
- Baggage handling.
- Waiting areas.
- Shops.
- Restaurants.
- Lounges.
- Restrooms.
- Passenger information.

**Aircraft infrastructure**

- Gates.
- Aircraft stands.
- Hangars.
- Maintenance facilities.
- Fuel stations.
- Ground service areas.
- Cargo loading areas.

**Airport operations**

- Air traffic control towers.
- Fire stations.
- Emergency facilities.
- Airport administration.
- Staff facilities.
- Technical buildings.

**External infrastructure**

- Parking garages.
- Roads.
- Public transportation.
- Bus terminals.
- Railway connections.
- Passenger drop-off zones.

### Advanced construction mechanics

Buildings should not simply provide capacity based on their existence.

Their actual functionality depends on their internal layout, connections and available infrastructure.

Examples:

- A terminal requires valid road access.
- A gate requires a valid connection to the apron and taxiway network.
- A hangar must have appropriate aircraft access.
- Passenger facilities require appropriate internal connections.
- Upper floors require stairs, escalators or elevators.
- Buildings must be enclosed with appropriate floors, walls and doors.
- Emergency facilities must be accessible.

### Terminal capacity

Terminal capacity should be calculated from the actual infrastructure.

The effective capacity is limited by the weakest operational subsystem:

- Floor area.
- Check-in capacity.
- Security capacity.
- Baggage handling.
- Restrooms.
- Seating capacity.

Adding more gates without increasing terminal capacity should not automatically increase passenger throughput.

### Construction controls

- WASD: Move camera.
- Q/E: Rotate camera.
- Mouse wheel: Zoom.
- Right-click and drag: Rotate view.
- R: Rotate selected building.
- X: Demolish.
- PageUp/PageDown: Change floor.

# INSTALLATION & DEVELOPMENT

## Requirements

- Docker.
- Docker Compose.
- Git.
- A CARTO account and API key.

## Start the game

Clone the repository and enter the project directory.

Copy the environment template:

```bash
cp .env.example .env
```

Configure the required environment variables, including your CARTO key.

Start the application:

```bash
docker compose up --build
```

Open:

```text
http://localhost:8080
```

On the first backend startup, the application imports approximately 9,500 airports from OurAirports.

The initial import normally takes 10–30 seconds.

## Production configuration

Always change the default database passwords before deployment.

Configure:

```env
DB_PASSWORD=your_secure_password
DB_ROOT_PASSWORD=your_secure_root_password
```

Start the production containers with the appropriate environment configuration.

Do not commit `.env` files or production credentials to version control.


To add a language:

1. Copy `frontend/js/lang/en.js`.
2. Translate all values.
3. Add the language to `LANGS` in `frontend/js/i18n.js`.
4. Add the language to `LANGS` in `backend/src/server.js`.
5. Run the internationalization checker.

```bash
node scripts/check-i18n.mjs
```

All player-facing text should use the internationalization system.
